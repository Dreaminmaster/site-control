# Site Control v2 接入验收（草案）

适用于所有新建和既有网站：不再强制每站安装独立 MCP。优先使用一个 Hub + 独立站点的 server-only adapter。已有 v1 合同仍然有效，任何接入能力不自动取得原站源码、托管或账号权限。

1. 记录原站标识、主机、版本、数据库、既有插件和已授权边界。维护接口和业务接口分离，独立 admin 必须保留。
2. Hub 只保存站点目录、脱敏维护配置和审计。默认不可传签证资料、学校数据、个人记录、登录凭证、私密 URL 或会话。
3. 所有者在 Hub 注册站点，单独配置一次性显示的站点令牌；只通过服务器 Secret 注入。撤销一个网站不影响其他网站。
4. 优先用出站 HTTPS 轮询协议，不需要站点被公开；如果平台不能安全持久执行，保留 Git/原站入口，不安装伪接口。
5. 首次只读心跳，验收身份和 revision；再批准一个可逆 fixture 变更，检查真实站点保存、回执、回滚、断线恢复和错误权限。
6. AI 只授权选定站点；读取和提案分别授权，不能自我批准。MCP OAuth 连接需要独立客户端实测，未实测不得宣称完成。
7. 对业务数据另外实现类型、领域校验、证据、审批、冲突和备份；严禁任意 shell、任意 SQL、任意网络转发或源码执行。GitHub 修改代码仍走受控 PR/部署。
8. 记录验收 PASS/FAIL/BLOCKED；真实部署、独立会话接管和恢复测试通过后，平台可独立使用；现有站点是否接入须由所有者逐个确认。

9. 平台允许在没有任何网站时先建立空 OAuth 授权。以后逐站授权即可；撤销某站同时移除其 AI 授权，重新连接不恢复旧权限。旧站接入由所有者另行决定，不是 Hub 完成的必要条件。
